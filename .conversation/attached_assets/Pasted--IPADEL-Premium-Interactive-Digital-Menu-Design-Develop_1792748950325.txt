# IPADEL — Premium Interactive Digital Menu
## Design & Development Brief for Replit Agent

Act as a senior UI/UX designer and frontend engineer. Build a premium, visually striking, fully interactive digital menu for **IPADEL**, a modern padel sports club.

The goal is to recreate the visual direction of the provided IPADEL menu concept: deep navy backgrounds, neon green accents, crisp white typography, premium sports-club photography, elegant product cards, and a polished editorial layout.

**This is a menu-browsing experience, NOT an online ordering or e-commerce website.**

Customers browse the available items, open product details, and save items to a personal **Memory Basket** to remember what they want to order physically at the counter.

---

## 1. Technology Requirements

Use pure frontend technologies only:

- HTML5
- Tailwind CSS
- Vanilla JavaScript (ES6+)
- Lucide icons or Lucide via CDN
- Google Fonts where appropriate

Do NOT use React, Next.js, Vue, backend frameworks, databases, authentication, or payment integrations.

Use a simple, organized project structure:

- `index.html`
- `src/input.css`
- `src/output.css` (if Tailwind CLI compilation is configured)
- `js/app.js`
- `js/data.js`
- `assets/` for the supplied logo and local images

If Tailwind CSS requires a build process, configure it properly so the project runs successfully in Replit. Do not assume Tailwind's browser CDN is suitable for production.

Keep product data separate from UI logic so the real menu can be added later without redesigning the website.

The final website must run correctly using Replit's preview.

Use the supplied original IPADEL logo. Do not redraw, replace, distort, or approximate it.

Brand colors:

- Neon Green: `#19F5A0`
- Secondary Green: `#00DDA0`

- Subtle Borders: translucent blue/cyan

Visual direction:

- Premium padel club
- Modern sports-tech aesthetic
- Athletic but sophisticated
- Strong typography and clear visual hierarchy
- High-quality drink photography
- Subtle court-inspired geometric details
- Soft green illumination used sparingly
- Smooth transitions and refined micro-interactions

Avoid excessive rounded cards, excessive glowing effects, random gradients, excessive animations, and generic restaurant-template styling.

The final result should feel like an actual branded digital product, not a generic template.

## 4. Drinks Catalog

Create a visually polished product browsing section.

Initially use fictional placeholder drinks only to demonstrate the interface. Make it easy to replace every placeholder with real menu data later.

Suggested placeholder categories:

- All Drinks
- Hot Drinks
- Cold Drinks
- Juices
- Water
- Energy Drinks

Use example products such as Espresso, Americano, Cappuccino, Latte, Iced Coffee, Fresh Juice, Water, and Energy Drink.

**Important:** These are temporary design placeholders, not the actual IPADEL inventory. Store all sample products in `js/data.js`, and clearly mark the data as replaceable.

Each product card should include:

- Product image
- Product name
- Optional short description
- Price placeholder or clearly marked demo price
- A clear `VIEW DETAILS` action
- A separate quick-add-to-memory action using a bookmark or plus icon

Use premium image crops, consistent image ratios, clean alignment, and readable prices.

Do not invent real prices or imply that placeholder prices are official.

Category filters must work in Vanilla JavaScript and visibly indicate the active selection.

Include a search field that filters products by name.

Add sensible empty states for searches with no results.

## 5. Product Details — Required Interaction

Clicking a product image, card title, or `VIEW DETAILS` must open a polished product-details modal or side drawer.

This is an essential feature.

The product details interface must include:

- Larger product image
- Product name
- Full description placeholder
- Price
- Category
- Optional size or variant selector when applicable
- Quantity selector with minus and plus buttons
- `ADD TO MEMORY` button
- Close button
- Optional related drinks section if it fits the design

All controls must work.

Selecting a different variant must update the displayed price when variant pricing is configured in the placeholder data.

The modal must:

- Open with a smooth fade and subtle scale transition.
- Close using the close button.
- Close when clicking the backdrop.
- Close with the Escape key.
- Prevent accidental background scrolling while open.
- Work properly on mobile, preferably as a bottom sheet or a full-width mobile drawer.

Do not show purchase, checkout, online payment, delivery, or order-submission actions.

## 6. Memory Basket — Core Feature

Create a persistent **Memory Basket** that allows customers to save the products they want to remember before going to the counter.

This is a personal reminder list, not a shopping cart or an online order.

Naming and messaging:

- `MEMORY BASKET`
- `YOUR PICKS`
- `Remember your favorites. Order at the counter.`

Implement the following:

1. Add a product from the product card.
2. Add a product from the details modal.
3. Increase or decrease the quantity of saved products.
4. Remove a saved product.
5. Clear the entire basket with a confirmation step.
6. Display the number of saved units in the header badge.
7. Display a separate count of unique products if useful.
8. Display each saved product's image, name, quantity, and price.
9. Calculate an estimated total based on the current displayed prices.
10. Persist the basket using `localStorage` so it survives page refreshes.
11. Restore the basket when the page is reopened in the same browser.
12. Update the basket interface instantly without reloading the page.

Use a compact floating action button or a header basket icon with a prominent but tasteful neon-green quantity badge.

Clicking it opens a refined side drawer on desktop and a bottom sheet on mobile.

Inside the drawer, show:

- Product thumbnails
- Product names
- Quantity controls
- Individual displayed prices
- Estimated subtotal
- Remove buttons
- Clear basket action
- A clear reminder: `Take your list to the counter to order.`

Use a strong empty state when no items are saved.

Example:
`Your basket is waiting.`
`Explore the menu and save what you would like to remember.`

Provide a `BACK TO MENU` action.

After saving an item, show a small, elegant toast:
`Added to Memory Basket`

When removing an item, update the badge and total immediately.

Do not implement a checkout, payment, order number, order confirmation, or pretend that the counter has received the basket.

The basket is only stored locally on the customer's device. It does not synchronize across devices and is not visible to staff.

## 8. Visual Design Details

### Layout

- Mobile-first responsive design.
- Premium desktop composition inspired by the supplied reference.
- Strong hero typography.
- Carefully controlled whitespace.
- Clear product hierarchy.
- Compact, elegant cards.
- Sticky or easily accessible category navigation.
- Consistent spacing and alignment.
- Avoid horizontal overflow.

### Product photography

Use high-quality, consistent drink images.

Prefer royalty-free image sources or reliable remote image URLs during prototyping. If a remote image fails, show a polished local fallback instead of a broken image icon.

Do not use unrelated food images in the drinks section.

The supplied IPADEL logo must be used wherever appropriate.

### Motion

Use CSS transitions and Vanilla JavaScript.

Include:

- Smooth category switching.
- Gentle image hover zoom.
- Subtle card elevation.
- Smooth details-modal transitions.
- Animated basket badge updates.
- Elegant toast notifications.
- Respect `prefers-reduced-motion`.

Animations should feel premium and controlled, never bouncy or distracting.

### Typography

Use a strong modern sans-serif such as Space Grotesk for headings and Inter for body text, if they render reliably.

Use bold uppercase typography selectively for section headings, with comfortable body-text sizes.

## 11. Code Quality and Architecture

Keep the implementation straightforward and maintainable.

Suggested data model:

Each product should support:

- `id`
- `name`
- `category`
- `description`
- `image`
- `price`
- `variants` (optional)
- `featured` (optional)
- `available` (optional)

Separate:

- Product data
- Product rendering
- Filtering and search
- Product details
- Memory Basket state
- Local storage
- Toast notifications
- Navigation

Use stable product IDs in localStorage, and gracefully handle invalid or outdated saved data.

Do not store the entire product database in localStorage; persist only the user's saved product IDs and quantities where practical.

This project is a frontend-only digital menu with a locally persistent Memory Basket.
