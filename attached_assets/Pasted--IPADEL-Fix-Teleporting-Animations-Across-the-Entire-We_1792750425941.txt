# IPADEL — Fix Teleporting Animations Across the Entire Website

Act as a senior frontend animation engineer. The existing IPADEL website has a critical motion-quality issue: animations feel like teleportation rather than smooth transitions.

Examples:
- Product images suddenly shrink when hovered.
- Buttons change size or appearance instantly.
- The Memory Basket drawer appears immediately instead of sliding smoothly.
- Modals and interactive elements pop into existence without a proper entrance.
- Hover effects feel abrupt and inconsistent.

**Your task is to diagnose and fix the underlying causes across the entire existing project. Do not redesign the website or remove working functionality.**

## 1. Audit Before Editing

Inspect all existing CSS, Tailwind classes, JavaScript interaction handlers, modal logic, basket drawer logic, and animation code.

Search for:

- Missing or overridden `transition` properties.
- Conflicting Tailwind transition and duration classes.
- CSS rules that set `display: none` and `display: block` for animated elements.
- JavaScript that toggles classes or inline styles in the wrong order.
- Elements being removed from the DOM before their exit animation completes.
- Immediate changes to `transform`, `opacity`, `scale`, `height`, or `visibility`.
- Conflicting hover selectors and JavaScript hover handlers.
- CSS animations that are being restarted or canceled unexpectedly.
- GSAP animations that are overwritten or interrupted by other scripts.
- Duplicate event listeners.
- Missing initial animation states.
- Elements that are rendered directly into their final state without an entrance transition.

Do not assume the problem is simply a missing `transition-duration`. Identify the actual causes first.

## 2. Establish a Consistent Motion System

Create a small, reusable motion system using CSS custom properties:

```css
:root {
  --ease-standard: cubic-bezier(0.22, 1, 0.36, 1);
  --ease-interactive: cubic-bezier(0.2, 0.8, 0.2, 1);

  --duration-fast: 220ms;
  --duration-normal: 350ms;
  --duration-smooth: 450ms;
  --duration-panel: 400ms;
}
```

Use these as starting points, then adjust them according to the component.

Use `transform` and `opacity` for most animations. Do not animate layout properties unnecessarily.

All hover, focus, active, opening, and closing states must have intentional and consistent motion.

## 3. Fix Product Image Hover

Product images must never shrink or jump instantly.

Implement a smooth image hover effect:

```css
.product-card__image {
  transform: scale(1);
  transition: transform 450ms var(--ease-standard);
  transform-origin: center;
}

.product-card:hover .product-card__image {
  transform: scale(1.045);
}
```

Adapt the selectors to the actual project.

Important:
- Preserve the existing image dimensions and aspect ratio.
- Keep the image inside its intended clipping container.
- Do not change the image's width or height on hover.
- Remove conflicting transform rules.
- Do not let JavaScript and CSS fight over the same transform.
- Avoid applying a scale-down effect on hover unless it is intentional.
- On touch devices, provide a subtle pressed state rather than a permanent hover state.

The result must feel like a gentle cinematic zoom, not a sudden resize.

## 4. Fix Every Button Interaction

All buttons and interactive cards must respond smoothly.

Implement:

- Smooth background and border-color transitions.
- Subtle hover elevation where appropriate.
- Gentle icon movement.
- Controlled active/pressed feedback.
- Clear keyboard focus states.

Example:

```css
.button {
  transition:
    color 250ms var(--ease-interactive),
    background-color 250ms var(--ease-interactive),
    border-color 250ms var(--ease-interactive),
    box-shadow 250ms var(--ease-interactive),
    transform 250ms var(--ease-interactive);
}

.button:hover {
  transform: translateY(-2px);
}

.button:active {
  transform: translateY(0) scale(0.985);
}
```

Adapt this to existing button classes and preserve the IPADEL navy and neon-green design system.

Do not apply the same hover transform indiscriminately to every button.

## 5. Fix the Memory Basket Drawer

This is a priority issue.

The drawer currently appears instantly. Replace the abrupt show/hide behavior with a real entrance and exit animation.

Expected behavior:

**Opening**
- Backdrop fades from transparent to visible.
- Drawer slides smoothly in from the right on desktop.
- On mobile, use an appropriate bottom-sheet entrance if the current layout supports it.
- Content appears naturally without a sudden jump.

**Closing**
- Drawer slides back out.
- Backdrop fades away.
- The drawer is hidden or removed only after the exit transition completes.

Suggested CSS:

```css
.memory-backdrop {
  position: fixed;
  inset: 0;
  opacity: 0;
  visibility: hidden;
  pointer-events: none;
  transition:
    opacity 300ms ease,
    visibility 300ms ease;
}

.memory-drawer {
  transform: translateX(105%);
  visibility: hidden;
  transition:
    transform 400ms cubic-bezier(0.22, 1, 0.36, 1),
    visibility 400ms;
}

.memory-drawer.is-open {
  transform: translateX(0);
  visibility: visible;
}

.memory-backdrop.is-open {
  opacity: 1;
  visibility: visible;
  pointer-events: auto;
}
```

These are reference patterns, not assumptions about the current DOM. Adapt them to the existing layout and avoid conflicting rules.

**Important:** Do not toggle `display: none` to `display: flex` and expect the drawer to animate. Use a persistent element with animation states, or implement a correct mount/animate/unmount lifecycle.

Ensure the drawer can still be closed with its close button, the backdrop, and Escape. Preserve basket contents and localStorage behavior.

## 6. Fix Product Modals and Toasts

Apply the same principles to every modal and notification.

Product modal:
- Fade the backdrop in and out.
- Use a subtle scale-and-rise entrance.
- Reverse the animation on close.
- Do not make the modal jump to its final position.
- Prevent repeated clicks from creating inconsistent states.

Suggested modal states:

```css
.product-modal {
  opacity: 0;
  transform: translateY(12px) scale(0.985);
  transition:
    opacity 300ms ease,
    transform 400ms var(--ease-standard);
}

.product-modal.is-open {
  opacity: 1;
  transform: translateY(0) scale(1);
}
```

Ensure visibility and DOM lifecycle are handled correctly so the browser can actually render the initial state before the animation starts.

Toast:
- Fade in with a subtle upward movement.
- Stay visible for its intended duration.
- Fade and slide out instead of disappearing instantly.

Do not introduce new libraries if the existing CSS and JavaScript can solve these issues reliably.

## 7. Fix Animation Initialization and Rendering

Check whether animations fail because classes are added before the browser renders the initial state.

Where necessary, use a deliberate two-stage state change or `requestAnimationFrame` so the initial state is painted before the active state is applied.

Avoid adding arbitrary `setTimeout` calls everywhere.

Do not force synchronous layout measurements unless necessary.

If GSAP is already installed, inspect its timelines, easing, and cleanup logic before deciding to use it. Do not mix competing CSS and GSAP animations on the same property.

## 8. Respect Reduced Motion and Touch Devices

Add a reduced-motion fallback:

```css
@media (prefers-reduced-motion: reduce) {
  *,
  *::before,
  *::after {
    scroll-behavior: auto !important;
    animation-duration: 0.01ms !important;
    animation-iteration-count: 1 !important;
    transition-duration: 0.01ms !important;
  }
}
```

Also ensure touch devices do not retain misleading hover styles after tapping.

## 9. Final Verification

Test every interaction manually in the browser:

1. Hover over several product images.
2. Move the pointer on and off product cards repeatedly.
3. Hover over buttons and icons.
4. Open and close the Memory Basket repeatedly.
5. Open and close product details.
6. Add and remove items while the drawer is open.
7. Navigate between Drinks, Canteen, and the homepage.
8. Test at desktop and mobile viewport sizes.
9. Check rapid repeated clicks for visual glitches.
10. Confirm there are no console errors or broken basket behaviors.

Inspect the final implementation rather than merely adding CSS and declaring the issue fixed.

**Acceptance criterion:** Every visual state change must feel intentional and smoothly animated. No sudden image shrinking, teleporting drawers, abrupt button changes, or disappearing modals. Fix the root causes while preserving the existing design, content, navigation, and Memory Basket functionality.
